# doc/test catalogue per-test-table exemptions.
#
# The generated `### <path> (N)` sections that answer with a SUMMARY -- a
# `| Category | Tests |` grouping -- instead of a row per test, and the
# reason each one does. See script/test/drivers/catalog_description.sh
# ("Reach") and doc/test/TEST.md.
#
# Why the file exists. The description rule is enforced over catalogue
# ROWS, so a section with no per-test rows was outside it -- and it was
# outside it by TABLE SHAPE, which nobody had to decide, nobody could see
# and nothing bounded: 606 tests, 19% of the suite, sat outside a REQUIRED
# field while both gates reported clean. Summarising is a legitimate
# answer for a spec whose cases are near-identical assertions; being
# outside a required rule by accident is not. So the answer is written
# down here, per section, with the reason, and the lint prints how much of
# the suite it accounts for on every run.
#
# Format: <spec path> TAB <reason>, sorted LC_ALL=C, no duplicates. The
# reason is prose for a reader, not a token: it says what makes a row each
# the wrong shape for THAT section. A blank one, or a `-`, is refused --
# it is the same silence the rule refuses in a row's Description cell.
#
# This file is NOT shrink-only, and that is the difference between it and
# the baseline: the baseline holds debt, this holds decisions, and a spec
# written tomorrow may honestly belong here. What an addition costs is a
# line, a sentence, and the `# entries:` count below, in front of a
# reviewer. Giving a listed section a real per-test table makes its line
# STALE and the lint refuses it, so an exemption cannot outlive its reason.
#
