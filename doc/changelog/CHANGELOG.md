# Changelog

All notable changes to base are documented under `doc/changelog/`, **one
file per 0.Y series**. This file is the index: it names every series, the
dates it spans, and the BREAKING entries it carries. That last part is what
makes it worth reading rather than a table of contents -- the reader this
file is for is a downstream maintainer mid-upgrade, asking what changed
between their version and the target and what will break them.

At 0.x the minor is the breaking axis, so the 0.Y series is the natural
unit: a reader opens exactly the one file that spans their upgrade instead
of the single file this replaces -- over 680 KiB across 108 sections.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Writing an entry: [CONVENTIONS.md](CONVENTIONS.md). New entries go under
`## [Unreleased]`, which lives in the series file currently being written --
the row below marked *in progress*.

The block below is GENERATED from the series files by
`script/release/changelog_index.sh` (`just release changelog-index`), and
`just test lint --changelog-layout` re-derives it and fails on any
difference. Do not edit it by hand: an index nothing re-derives goes stale
on the first series nobody remembers to add, and a missing row reads exactly
like a series that does not exist.
